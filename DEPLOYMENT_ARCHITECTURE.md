# Архитектура развёртывания (Timbrabot)

## Целевое production-разбиение

| Компонент | Платформа | Назначение |
|-----------|-----------|------------|
| Основной сайт **timbra.tv** | Vercel | Публичный маркетинговый сайт (`website/`), позже |
| Дашборд бота **bot.timbra.tv** | Railway (web service) | Next.js: OAuth, панель, API (`discord-bot-dashboard/`) |
| Процесс Discord-бота | Railway (worker / отдельный сервис) | `discord.js`, welcome, авто-роли (`discord-bot/`) |
| Общее хранилище (цель) | **Postgres** | Единый источник правды для конфигов и состояния бота |
| Локальная разработка / MVP fallback | **JSON в `shared-data/`** | `config.json`, `bot-state.json`, ассеты, шрифты |

## Персистентность

- Переменная **`PERSISTENCE_DRIVER`** (см. `.env.example`): сейчас поддерживается **`json`** — поведение как у MVP (файлы под `SHARED_DATA_DIR` / `../shared-data`).
- Режим **`postgres`** зарезервирован под будущую реализацию; при включении без кода приложение завершится с явной ошибкой.
- **Важно:** хранить **локальный JSON** как единственный источник правды при **разнесённых** сервисах (бот на Railway + дашборд на Railway **без** общего диска) **небезопасно**: каждый процесс увидит свой файловый каталог. Нужны либо **общий смонтированный volume**, либо **БД** (например Postgres).

## Связь с кодом

- Абстракции: `discord-bot-dashboard/lib/persistence/*`, `discord-bot/lib/persistence/*`.
- Черновик схемы БД: `docs/POSTGRES_SCHEMA_DRAFT.md` (только документация).
