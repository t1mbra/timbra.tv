# ROADMAP

## Overview

У проекта сейчас три главных направления:

1. `discord-bot` - живой Discord-бот **Рогатик**
2. `discord-bot-dashboard` - панель управления ботом
3. `website` - основной сайт `timbra.tv`

Главный принцип развития:

- сначала довести до устойчивого состояния бота и dashboard
- потом собрать сайт как медиа-хаб Тимбры
- потом соединить все автоматизациями и контентными сценариями

---

## Current mainline

Исторически ветка `feature/postgres-persistence` пережила свою исходную задачу и стала главным интеграционным стволом разработки.

Текущий актуальный mainline проекта:
- `develop`

Практически это означает:
- все новые рабочие feature-ветки должны ответвляться от `develop`
- Railway должен смотреть именно на `develop`
- старые `feature/*` и `hotfix/*` ветки постепенно переводятся в статус исторических

---

## Current product state

### Welcome
Реализовано:
- delivery modes
- общий message editor
- send test
- текстовые сценарии
- вложения изображений
- базовая система style settings

Открыто:
- random welcome messages
- баги в `Стиль приветствия`
- баги / polish в card/image-card части

### Farewell
Реализовано:
- отдельный lifecycle-модуль
- канал
- сообщение
- send test
- live runtime

### Auto-roles Core
Реализовано:
- множественные роли для участников
- роли для ботов
- отдельные роли для ботов
- задержка для участников
- задержка для ботов
- ожидание membership screening
- безопасный runtime на join/update
- polished UI core

Не реализовано:
- синхронизация ролей для уже существующих участников

## NOW

### 1. Ускорить и стабилизировать `/servers`
Цель:
- страница выбора серверов открывается быстро
- статус подключения бота не врет
- после подключения сервер становится доступным для управления

Задачи:
- внедрить `shared-data/bot-state.json`
- бот должен писать список guilds, где он реально состоит
- dashboard должен читать bot-state вместо медленных per-guild connection checks
- `/api/discord/guilds/[guildId]/connection` оставить только для:
  - connect modal
  - polling после invite
- сохранить сортировку:
  - подключенные выше
  - неподключенные ниже
  - внутри по алфавиту

### 2. Проверить lifecycle live end-to-end
Цель:
- lifecycle-функции реально работают на живом сервере, а не только через send test

Проверить:
- Welcome для обычного участника
- Welcome для бота
- Farewell при выходе участника
- Auto-roles для участника
- Auto-roles для бота

Подтвердить:
- `skipBotAccounts` влияет только на welcome
- auto-roles независимы от welcome/farewell
- text-стиль работает
- embed-стиль работает
- вложения и изображения там, где уже поддержаны, работают
- логи бота понятные и пригодны для эксплуатации

### 3. Исправить баги в `Стиль приветствия`
Цель:
- модуль `Приветствие` ощущается законченным и больше не требует постоянной перекройки

Задачи:
- дополировать `Text`
- дополировать `Embed`
- убрать баги и UX-проблемы в `Стиль приветствия`
- убрать баги в card/image-card зоне
- сохранить текущую общую архитектуру:
  - общий composer
  - style selector ниже
  - style-specific settings отдельно
- не ломать редактор ради мелкого визуального полиша

### 4. Random welcome messages
Цель:
- `Приветствие` может выбирать случайный вариант из нескольких сообщений

Задачи:
- список welcome-сообщений
- случайный выбор при live send
- понятный UI для управления вариантами
- send test и preview не должны стать хаотичными
- не ломать текущий общий editor
